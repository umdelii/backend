스프링부트 동작방식
1. DispatcherServlet : 웹 요청을 처음에 받음
2. 요청 경로 파악 후 HandlerMapping, HandlerAdapter 객체 사용
3. 적절한 컨트롤러로 요청 넘김
4. 컨트롤러 동작 후 결과를 템플릿과 함께 리턴
5. 클라이언트 화면에 출력

템플릿규칙
void : http://localhost:8080/home 요청 시 사용했던 경로에서 마지막에 존재하는 경로에 .html을 붙여서 찾기

void : http://localhost:8080/content/home -> content/home.html
    ex. http://localhost:8080/board/add -> board/add.html

String : return 값에 html을 붙여서 찾기

컨트롤러
@Controller 어노테이션을 붙이면 : 해당 클래스가 컨트롤러 역할임을 명시
    - 프레임워크가 해당 클래스를 관리(new 하겠다. 객체생성하겠다.)
    - 경로 중복 금지!!

템플릿 : html, java 코드 사용가능해야함
 => thymeleaf
        자바코드 쓰는 방법
        <p>[[${info.addr}]]</p>
        <p>[(${info.addr})]</p>
        <input th:value="${info.addr}"></input>
        <p th:text="${info.addr}"></p>

404 = 경로없음

 http://localhost:8080 -> 컨트롤러 찾기 -> 컨트롤러 코드 실행 -> template 작업 -> template 화면 보기

 http://localhost:8080/board/read?no=1 - ?뒤는 파라메터(매개변수)


 @RequestParam = http 요청의 파라미터를 컨트롤러 메소드의 매개변수로 바인딩(연길)
    public void postCalc(int num1,int num2){}: 이름 똑같이 한다면 @RequestParam 없이도 가능
    public void postCalc(@RequestParam int num1,@RequestParam int num2){}:
    public void postCalc(@RequestParam("num1") int number1,@RequestParam int num2){}: 매개변수 이름이랑 다를때
    public void postCalc(@RequestParam(required = false, defaultValue = "0") int num1,@RequestParam(required = false, defaultValue = "0") int num2){}: 
        required -> 값이 안들어올수도있음, defaultValue -> 디폴트 값

Model : 스프링프레임워크가 제공해줌
 하는 일 : 컨트롤러가 뷰(사용자가 보는 화면)에 데이터를 전달하기 위해 사용하는 인터페이스
 model.addAttribute("key",value) , key 값은 중복 안되게

@ModelAttribute("키") : Model 객체와 하는 일이 똑같음
Model : 뷰로 데이터 전달
@ModelAttribute("키") : 뷰로 데이터 전달 + (데이터 바인딩)

RedirectAttributes : 리다이렉트가 발생한 후 데이터를 일회성으로 전달하기 위해 사용하는 인터페이스
 1. 주소줄 이용 : rttr.addAttribute()
 2. HTTP session을 임시로 사용 : rttr.addFlashAttribute()
