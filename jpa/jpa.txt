@ManytoOne(optional = true) -> null 허용하는 조일컬럼이 생성됨
    허용하지않으려면 false
    join ~ on ~ : 자동으로 join 처리

@ManyToOne(optional = false, fetch = FetchType.LAZY)
 - 외래 키 테이블 정보를 조회하지 않음 => join하지 않음
 - 외래 키에 해당하는 객체 탐색 시 => LazyInitializationException 오류가 뜬다


@JoinColumn(name = "")
 - 따로 name 설정안하면? 부모키가 team_id면 team_team_id 이렇게 만들어줌 ...
 - 테이블명_기본키명

@OnetoMany 
 - @ManyToOne의 상대방 클래스에 작성
 - 왜 걸까?
    원 sql의 외래키 개념과 불균형이 발생됨(객체에서는 양쪽에서 접근이 불가능하다) => 해결하기 위해 양쪽에 객체 관계를 설정해서 jpa에 알려줘야해
 - 조금 문제가 있다... what?
    얘는 fetch가 기본 LAZY기때문에 조인구문으로 처리하지않음
FetchType.LAZY(지연로딩) => 본인 테이블의 정보만 먼저 가져오기때문에 조인관계 테이블에 접근시 LazyInitializationException이 뜬다
    해결법 1. 해당 메소드에 @Transactional을 붙이기
        but, 본인, 조인관계 테이블 접근 시 각각의 select 구문으로 처리(select 두번함) (이게 더 처리속도가 빠른 경우도 있어)
    해결법 2. left join으로 처리하게 하자(FetchType.EAGER(즉시로딩))

@OnetoOne : 기본적으로 내부조인으로 처리

그래서 기본적으로 @ManyToOne이나 @OneToOne은 -> FetchType.LAZY 설정을 바꾸고 => @Transactional 하거나 / @EntityGraph(필요할때만 join 구문 사용) 한다

@EntityGraph(arritubePaths = {"join으로 가지고 올 테이블 변수명}, type = EntityGraphType.LOAD(OR FETCH))

@OnetoOne(mappedBy = "부모키있는테이블변수명")
 = 외부조인으로 처리

객체 그래프 탐색
FetchType.EAGER(즉시로딩) : 연관된 객체를 조회하는 시점에 바로 사용
FetchType.LAZY(지연로딩) : 연관된(외래키) 객체를 실제 사용하는 시점에 데이터베이스에서 조회

1. 단방향(@ManytoOne)
    - 내부조인으로 처리
    - fetch = FetchType.LAZY를 통해 해당 테이블 정보만 조회 
        => 해결 1. @Transactional
        => 해결 2. @EntityGraph
2. 양방향(@ManytoOne/@OnetoMany)
    - @OnetoMany : default 값이 LAZY다
3. 단방향(@OnetoOne)
    - @ManyToOne 이랑 똑같다.
4. 양방향(@OneToOne/@OneToOnej)
    - 외부조인하네? left join

영속성 관리
 => 내부적으로 Persistence Context를 이용해 관리함

Persistence Context
 1차 캐시 : 조회한 엔티티를 저장, 같은 엔티티 조회 시 재쿼리 실행 방지
 변경 감지 : dirty check  (값 변경 시 update 구문 실행) 
 엔티티 동일성 보장 / 라이프 사이클(New,Managed,Removed,Detached) 관리
 지연 로딩(Lazy Loading) = 프록시 유지

 부모 / 자식
 @OneToMany(mappedBy = "부모변수명", cascade = {CascadeType.PERSISIT, CascadeType.REMOVE}, orphanRemoval = true)
    cascade = 하나의 엔티티에 발생하는 과정을 다른 엔티티에도 전파
    CascadeType.PERSISIT : 부모 삽입 시 자식도 삽입
        코드 상은 ArrayList에 자식 추가 => 부모만 save()
    CascadeType.REMOVE : 부모 삭제 시 자식도 삭제
        코드 상은 부모만 제거 
    orphanRemoval : 고아객체
        코드 상 부모 엔티티 컬렉션에서 자식 엔티티의 참조만 제거 => 부모만 save()
        p.getChilds().remove();

    개념
        javascript 타입 : number, string, boolean, [], undefined, null ...
        js의 타입 전부 사용가능 
        + typescript 제공 타입 : tuple, any, unknown, void, never, enum, type ...
        
        tuple 모양 [타입,타입,타입...]
            순서, 길이 고정
        
        any : 뭐든 넣을 수 있음, 그렇게까지는 쓰이지 않음

            as : 타입 단언

        void : 반환값에 사용

        never : 에러를 반환하거나 절대 종료되지 않는 함수의 타입으로 사용 / never가 쓰인 함수 호출 다음부터 모든 밑의 코드는 실행x

        enum : 상수열거형

        type : enum과 비슷한 역할로 쓰임

    여러 컴포넌트에서 비슷한 기능을 공유할 경우
    useState() : 렌더링과 관련 
                부모 렌더링 시 자식도 같이 렌더링
                자식의 state가 변경될 때는 자식만
    useState()로 상태를 저장, 변경값을 주어서 화면상 변경이 생기면 기존 DOM를 파괴하고 re렌더링해서 화면에 뿌림
    useRef() : 렌더링과는 별개로 변수를 사용하거나, DOM 요소에 직접 접근할 때 사용
                렌더링 될 때 값이 초기화 되지않음
    useEffect() : 리액트 컴포넌트의 생명주기에 맞춰 어떤 작업 수행 시 사용
                1. Mounting : DOM이 생성되고 웹 브라우저 상에 나타나는 상황(컴포넌트가 처음으로 렌더링되는 시점)
                2. Unmounting : 마운트 반대과정(컴포넌트를 DOM에서 제거하는 시점)
                3. Updating : props 변경 / state 변경 / 부모 컴포넌트가 리렌더링 될 때
    useReducer() : state를 한번에 관리 
                프로젝트의 상태 로직이 복잡할 때 사용
    useMemo() : 시간이 많이 걸리는 함수, 리렌더링 되지 않아도 되는 컴포넌트에 적용
        useMemo(()=>({}),[]) : 첫 번째 인자의 함수는 기본적으로 컴포넌트가 리로드될때마다 새로운 함수로 인식
                                [] 안에 들어있는 기준이 변경될때만 새로운 함수로 기억해라
    useCallback() : 자식에게 내려가는 함수가 많고, 렌더링 비용이 클때

    Context
        useContext() : 상태를 어디서든 쓰게 만들 때 사용
        ==> useReducer() + useContext() => 상태처리
        redux 라이브러리
